# Authentication and authorization implementation status

Updated 22 October 2026. This records repository implementation, not production deployment.

| Recommendation                              | Implementation status                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enforce authorization on the server         | Undeclared endpoints deny access. Business checks validate scope relationships and membership. Native organization mutations require a group identity administrator with MFA.                                                                                                                                                            |
| Separate identity and business authority    | Identity roles manage accounts. Scoped business roles grant permissions; identity administrators do not automatically receive business access.                                                                                                                                                                                           |
| Review privileged access independently      | Weekly assignment reviews and completed emergency-access reviews require an independent operator, evidence, and a decision against the current grant. Review history is retained.                                                                                                                                                        |
| Make domain admission stable                | Explicit team-ID-to-domain bindings replace name-based admission. A migration backfills existing recognized team names. New teams require an explicit binding.                                                                                                                                                                           |
| Remove stale access after transfers         | Membership deletion atomically revokes matching assignments and ends emergency access. Rejoining does not restore revoked grants.                                                                                                                                                                                                        |
| Offboard atomically                         | Authorized administrators can suspend an account, remove memberships, revoke sessions and business grants, and retain its audit history in one transaction.                                                                                                                                                                              |
| Recover accounts after all factors are lost | An operator records verification evidence. An independent super-admin approves an unexpired request against an unchanged account snapshot. Completion revokes old credentials, factors, and sessions, and issues a temporary password requiring replacement.                                                                             |
| Protect privileged operations               | Recent authentication, MFA, no self-approval, and restrictions on impersonated sessions apply to sensitive recovery and access operations.                                                                                                                                                                                               |
| Support passkey adoption                    | Passkeys are available. Recovery removes old passkeys and requires reenrollment. Universal passkey enforcement is not configured.                                                                                                                                                                                                        |
| Connect an authoritative HR system          | Frappe HR (v16) is the employee record. The core service issues ordinary accounts to active employees and offboards leavers on their relieving date ([ADR 0004](../adr/0004-hr-record-drives-joiners-and-leavers.md), [setup](frappe-hr-setup.md)). Transfers and every grant stay manual. Not yet exercised against a live Frappe site. |
| Expand domain permissions                   | `domain:administer` is implemented. Further permissions should accompany actual domain workflows.                                                                                                                                                                                                                                        |
| Establish operating procedures              | Recovery verification, independent escalation, and weekly access review procedures are documented in [Access operations](access-operations.md). Named staff and production delivery/recovery exercises still require organizational action.                                                                                              |

## Release verification

Repository checks and test-database migration exercises do not establish that production has been migrated or deployed. Follow [Access-control rollout](access-control-rollout.md), migrate before deploying the application changes, and verify the configured notification delivery and operator assignments in the target environment.

## Admin-managed operations follow-up

- Updated the operating procedure for a company without an HR system. The company owner designates a people-operations lead and backup; managers authorize employment changes and notify operators at the effective cutoff. A restricted register records instructions and completion, linked by application account ID. A reusable change record, initial roster reconciliation and monthly whole-staff reconciliation accompany weekly privileged reviews. These procedures do not assign real staff or create automated reminders.
- Repeated the full administration browser matrix after the earlier fixes: 69 passed, two platform skips and one mobile Chromium editor failure across 72 cases. All identity/access lifecycle cases passed across Chromium, WebKit and mobile Chromium, including recovery, independent reviews and offboarding. The failed editor workflow reported an intermittent ResizeObserver loop notification; four immediate isolated repeats passed. The full matrix is not clean and the intermittent editor error remains unresolved. No product code changed in this follow-up.
- Operating-document formatting and working-tree whitespace checks passed. Named operators, real employee reconciliation and target-environment acceptance remain organizational work.

## Frappe HR connector, 26 October 2026

- Added the `hr` module: a signed Frappe webhook and an hourly reconciliation (advisory-locked across replicas) issue an ordinary account to an active employee and offboard a leaver on their relieving date. Accounts are linked to HR records by employee id in `hr.employee_account`; an account already holding the company email is adopted rather than issued again.
- Issuing refuses a personal email equal to the workspace address, in the core service for every caller and in the admin issue form.
- Notification outbox: a drainer that stalls past the reclaim window can no longer overwrite the newer claim's outcome, and an out-of-order provider receipt can no longer move a delivered message back to sent.
- The activity timeline attributes HR-driven events to Frappe HR instead of "Deleted operator".
- Verified: lint, type checks, the core unit suite (137) and all core integration suites (56) passed. In Chromium the auth browser suite passed (9 of 9, now in parallel under Playwright test locks) and the admin suite passed 23 of 24; the failure was the intermittent ResizeObserver loop notification recorded above. The editor tests now excuse that exact browser notice and nothing else; the editor file then passed twice over (10 runs). WebKit and mobile Chromium then passed in full: auth 18 of 18, admin 46 with two platform skips. Firefox was not run; it fails to launch on the development machine. No live Frappe site has been connected.

## Remaining external acceptance

A production/staging target and its access have not been identified. Production migrations, deployment, verified email delivery and a restore using that environment's backup infrastructure remain unverified. Named primary/backup operators and their independent MFA accounts must be assigned by the organization. Do not mark these complete based on local tests.

The selected authentication policy remains MFA for privileged accounts with passkeys available for everyone. A universal passkey mandate has not been enabled; adopting it requires a supported-device and enrollment rollout. Further domain permissions are added with real protected operations, rather than unused permission names.
